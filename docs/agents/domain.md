# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root defines domain terms.
- `docs/adr/` holds architecture decision records.

## Before exploring

Read the root glossary and ADRs relevant to the work.

If these files are absent, proceed silently. Domain modeling creates
them when terms or decisions are resolved; setup leaves them absent.

## Vocabulary

Use the glossary's terms in issue titles, proposals, hypotheses,
test names, and other output that names domain concepts.

For a missing term, check whether existing vocabulary already fits.
Record real gaps for domain modeling.

## Decisions

When a proposal contradicts an existing ADR, name the ADR and explain
why the decision should be reconsidered.
